# 第八轮：连续动作与失败诊断

## 目标与计划

1. 增加通用 `pawn.ability_casting` 只读属性，让计划等待真实施法 Job 结束后再发下一条动作。
2. 失败、阻塞、不支持、预算耗尽和取消时，在清理 Job 之前保存有界对象快照、条件及等待进度。快照失败不能覆盖原始失败。
3. 保持九个 MCP 工具及现有参数兼容；不开放代码执行或反射入口。
4. 验证 Python schema、C# 诊断边界及双版本真实引用编译；必要时用独立 profile 做 1.7 后台正负例验证。
5. README 记录证据与限制，分别标明离线、编译及真机结果。

## 原理

效果已经出现不代表施法 Job 已结束；等待 `CurJob.ability == null` 可避免下一次施法被 `CanQueueCast` 拒绝。该属性只反映当前标准 Ability Job，不代表技能成功、冷却归零或自定义框架完成。

失败诊断只读取本轮绑定对象，优先当前步骤直接引用，再补最近动作的 actor/target，最多四个别名；不扫描地图或第三方私有字段。保留当时的作业与状态，随后照常清理。诊断是证据，不自动推断责任 Mod。

五项计划均已完成本轮限定范围。126 项 Python 离线测试、pip check、compileall 通过；Agent 两版真实引用编译零警告/错误；C# 两版离线诊断边界/序列化及通信检查通过。离线 C# 检查没有访问真实游戏对象。

## 踩坑

- 协议 `WireJson.Serialize` 返回 UTF-8 字节；测试应显式解码再检查 JSON 文本，不能按字符串返回值猜测。
- 诊断对象读取逐项隔离，快照超限先丢弃附加诊断，保留原业务失败。`objects_truncated` 和 `diagnostics_omitted` 区分对象数与报告字节预算。
- `pawn.ability_casting=0` 不等于冷却归零；连续技能示例使用两个独立 Ability，并额外检查第二次冷却。
- 首次取消例在 quicktest 生成 Pawn 时出现 `TicksAbs/gameStartAbsTick` 红字，栈经过婚姻关系与 Tale 创建；不读取其他 Mod 源码、不直接归因或屏蔽。原始三例汇总被只读审计拒绝，原样保留。补上验证脚本对所有用例（包括负例/取消）的启动错误与覆盖门禁，并在最终完成标记后执行只读证据审计；审计失败会撤回完成标记。两个干净用例单独派生审计，取消例单独复跑。
