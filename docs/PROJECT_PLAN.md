## 1. 最终目标

让任意支持标准 MCP 的 AI / Agent，通过少量结构化工具调用，独立启动隔离的 RimWorld 测试进程、执行可复现的功能测试、获得带证据的结论、回收所属进程。覆盖 RimWorld 1.6 与 1.7。

**后台自主是硬性要求**：不移动真实鼠标、不注入系统键盘、不激活测试窗口、不抢占玩家正在操作的窗口，不要求用户接管开发者菜单。默认不是截图驱动，非视觉功能测试不需要模型看图。

项目完成必须覆盖建筑从正常放置到实际工作，而非只生成成品。物品、效果、UI 有独立能力边界，不能用建筑通过替代所有类别通过。

## 2. 不作虚假承诺

- 不能承诺任意 Mod、任意版本、任意机器完全兼容。必须公开测试矩阵、已知限制、跳过项和证据。
- 不能声称 Agent 对游戏绝对零影响：程序集加载、队列、Harmony 钩子和观测本身均有开销。目标是可测量的最小侵入，不修改被测行为，不掩盖异常。
- 不抢鼠标不等于没有 CPU / GPU / 显存 / 磁盘竞争。与玩家游戏并行的性能预算需要真机测量；默认仅一个测试 worker，资源不足时排队或暂停，不擅自争抢前台资源。
- 能在失焦时继续 Tick，不代表启动时不抢焦点，也不代表最小化后可以正常绘制 UI。三项分别验收。
- 无头模式不等于正常图形客户端。依赖渲染的 Mod 必须在具备图形能力的后台 worker 验证；缺失能力应报告不支持，不能悄悄改为前台运行。
- 无红字、地图就绪、能够直接调用方法，都不能替代正常玩家路径和明确功能断言。

## 3. 架构

```text
任意 MCP 客户端 / AI
  -> 简洁 MCP facade（标准 schema，无模型厂商依赖）
  -> 外部任务执行器（计划、进程、资源策略、证据、恢复）
  -> 版本化后台 worker（独立游戏进程 / 独立 profile）
  -> RimProbe Agent（白名单命令、有界主线程队列）
  -> 声明式组合计划 / 通用正常动作 / 类型化只读观察 / 独立断言（保留快捷 recipe）
```

MCP 是入口，确定性状态机才负责执行。不能要求模型反复决定什么时候搬材料、何时等 Tick、如何重试。CLI 与 MCP 共用同一执行核心；没有任何模型 API key 也应能够运行预定义测试。

1.6 保持 net472 / Unity 引用；1.7 保持 net10.0 / UnityStubs / Waylith 引用。共享协议与场景描述，分开引擎适配、构建产物、obj、日志策略和验证记录。未适配的新构建不得伪装成已验证版本。

## 4. 兼容与低侵入规则

1. 非 RimProbe 会话不激活 listener / patch / 探针任务；不要为了观测自动注入会写入正常存档的组件。
2. 保留当前显式会话启用策略；审计 Root.Update postfix 的必要性、耗时与其他 patch 所有者。优先最小观测钩子，不改参数、返回值，不跳过原逻辑，不全局拦截施工 / 搬运 / 工作方法来强制成功。
3. 不在查询中消耗游戏随机数，不随意重置 Rand，不更改正常游戏的全局 debug / godMode / 时间设置。测试场景内的环境设定必须显式记录。
4. 不遍历全部对象或序列化整张地图于每帧；空闲快速返回，采样、事件、日志和结果均有界。重任务不能长期堵塞主线程。
5. 场景准备和功能验证严格分开：可准备工人、地形、库存、供电设施；不可直接填满被测 Frame、强制完成建筑、直接设置 PowerOn 或直接生成预期产物后声称成功。
6. 只操作自建测试 worker 的 profile、对象和进程；绝不接管玩家正在玩的进程。不修改正常 ModsConfig、Prefs 或正式存档。
7. 建立基线对照：Core + Harmony；Core + Harmony + Agent；再分别加入目标 Mod 与指定 Mod 组合。比较日志、关键游戏结果、Tick 行为和开销。相同种子不是完整确定性的证明。
8. 不自动变更第三方 Mod 顺序、关闭冲突 Mod 或安装依赖以制造通过；依赖缺失、版本不符要清楚失败。运行配置记录排序、DLC、配置快照和程序集 / 场景指纹。
9. 排障时只把堆栈 / patch 所有者作为归因线索，不把新增红字一律断定为目标 Mod 的错。

## 5. 后台执行路线与门禁

第一优先级是实测启动到退出全过程不抢焦点；不只是成功后把窗口最小化。

| 路线 | 研究目的 | 不得越过的边界 |
|---|---|---|
| 引擎支持的无头运行 | 非渲染逻辑、放置、搬运、施工、部分功能 | 先验证能否完整加载地图和目标 Mod；不能假定所有图形初始化在无头模式安全 |
| 保留渲染的后台 / 隔离桌面 worker | 依赖图形的 Mod、UI 与视觉测试 | 必须验证无激活启动、后台 Tick、离屏截图、退出；不能使用切换玩家桌面或系统输入作为兜底 |
| 另一个 Windows 会话或专用测试机 | 同一桌面无法可靠满足后台约束时的可选部署 | 报告需额外环境，不宣称本机同桌面方案已成功；不自动切换或部署 |

Windows 隐藏控制台只影响控制台，不保证游戏窗口不激活；启动参数、窗口显示策略、独立桌面是候选措施，不是未经验证的结论。

自动验收应只读记录前台窗口和鼠标位置，检查启动、场景加载、报错弹窗、测试与关闭阶段；测试程序不向用户桌面发送输入。严格后台模式失败必须停止 / 返回明确错误，不得偷偷前台运行。鼠标采样不能单独证明没有注入，代码审计与运行观测要同时做。

引擎侧输入或控件事件仅限自有测试进程。UI 语义操作、UI 事件交互和最终视觉分别报告；直接调用按钮回调不能冒充真实命中测试。若无法后台验证，返回 unsupported，不要求玩家让出鼠标。

资源策略包括低优先级、单 worker、独立测试帧率 / 分辨率 / 速度配置、CPU 与显存预算、暂停和超时。策略会影响性能测试结果，必须写入报告；不对任意硬件承诺与前台游戏并行不卡顿。

## 6. 面向轻量模型的 MCP 设计

下列是拟议高层接口，不是当前已经存在的工具：

| 拟议工具 | 职责 |
|---|---|
| capabilities | 发现版本、后台能力、可用测试配方和功能适配器，按类别分页 |
| run_suite | 接收版本 / profile ID、Def 名与配方，校验后启动后台任务，立即返回 run_id |
| get_run | 返回紧凑进度或最终报告；支持有限等待，完成后不再要求循环查询 |
| cancel_run | 幂等取消，停止后续动作并回收所属资源，保留现场证据 |
| get_artifact | 按注册 artifact ID 读取白名单证据，默认只取摘要 / 相关片段 |

已有底层工具作为兼容 / 高级接口保留或通过显式工具配置提供，不强迫普通客户端暴露大量微操作工具。接口定稿前做兼容策略，不静默破坏已有工具。

- 使用标准 MCP、短描述、明确枚举、小而浅的参数结构、可靠默认值、有限分页。避免把几十种动作塞进无 schema 的万能 JSON 参数。
- 模型只需选择对象和测试意图；配方内部负责准备、执行、等待、采样、断言、清理。
- 运行任务使用 run_id / case_id / request_id；启动和写操作支持幂等键，模型重试不能创建重复进程或重复蓝图。
- 返回 status、stage、summary、next_action、error_code、evidence_ids、coverage；默认不发送完整日志、整地图或截图。
- 区分 passed、failed、blocked、unsupported、cancelled、inconclusive；只在实际覆盖断言后给 passed。
- 用可操作的错误和合法参数示例帮助弱规划模型恢复；不要求它读源码才能理解下一步。
- DeepSeek 等模型作为标准 MCP 客户端目标，不绑定任何特定厂商、型号、推理能力或专有 tool 扩展。模型实际调用兼容性与标准协议兼容性分别记录；未运行某模型不能宣称已验证它。
- 先验证不同 SDK / 客户端实现的 initialize、tools/list、tools/call、错误、取消与长任务流程，再按可用条件验证轻量模型端到端操作。

## 7. 建筑测试完整链

### 7.1 发现与准备

解析实际加载的 ThingDef、材料、尺寸、朝向、terrain / PlaceWorker、研究条件、工作量、所需技能、组成部件与依赖。不靠名称猜功能。

选择版本化场景配方，记录种子、地图配置、环境、DLC、Mod 排序、工人技能 / 工作优先级 / 日程、资源库存和测试契约。种子之外仍可能有非确定性来源；重跑证据和差异不能省略。

### 7.2 正常放置与拒绝路径

- 正例：合法地形、位置、朝向、材料、交互格与占地，走正常建造设计器的校验 / 下蓝图路径。必须核对自定义设计器和 PlaceWorker，不能仅靠低层直接 Spawn。
- 负例：占地冲突、地图边界、不支持地形、缺少支撑或不合法材料，验证应被拒绝且原因合理，不生成残留对象或新异常。
- 使用代表性组合起步，再提供扩展矩阵；未穷举材料和朝向必须明确覆盖范围。

### 7.3 供材与搬运

把材料放入可达库存，由真实 Pawn / WorkGiver / Job 正常寻找、预约、搬运、交付。观察缺料和工作原因，不直接写入蓝图 / Frame 的容器。

验证材料种类 / 数量、库存变化、蓝图到 Frame 的交接、预约释放，以及缺料 / 禁用 / 不可达时的预期等待。阻断后恢复条件，确认流程能继续，而不是永久卡住。

### 7.4 施工与完工

让工人通过正常工作链累计工作量，验证最终 Def、Stuff、Faction、朝向、占地、健康状态和初始化；成功后蓝图 / Frame 不残留。工人状态、材料和工作量形成可审计时间线。

施工自然失败等游戏机制必须归类并记录，不通过禁用正常机制强制通过；固定场景也不能保证所有第三方 Mod 没有随机性。模拟 Tick 超时与实际时间超时分开设置、分开报告。

### 7.5 实际功能

| 可识别类别 | 正常路径与断言示例 |
|---|---|
| 用电建筑 | 真实供电网络与供给；验证正常运行及断电后的预期行为，不直接设置电力状态 |
| 燃料建筑 | 正常加燃料工作、消耗、耗尽 / 补充后的变化 |
| 工作台 | 正常添加有效 Bill、工人取料 / 作业、产物与材料账目 |
| 存储建筑 | 正常存储规则、搬运、容量限制和拒绝物品 |
| 温控或周期设备 | 可控环境中的测量值 / 周期事件，等待真实 Tick，并写明容差 |
| 自定义 C# 建筑 | 显式测试契约或受信任适配器；没有契约时只能给已覆盖的通用结论 |

自动发现 Comp 只能帮助选择配方，不能推断全部正确业务语义。供电成功但功能契约未知，应报告功能项 unsupported，不能宣布建筑功能通过。

### 7.6 生命周期与证据

覆盖重复建造、取消 / 拆除、可支持时的安装搬移、存读档和再次运行。报告每项实际执行的步骤、断言、预期 / 实际值、失败阶段、日志片段、对象 ID 和覆盖缺口。

## 8. 其他测试类别

- 物品：可生成性、可达库存、拾取 / 装备 / 使用的正常路径、数量和耐久变化，以及显式触发效果；不以直接赋予效果替代物品使用。
- 效果：真实触发条件、目标、持续时间、叠加与清理，验证负例和异常；视觉效果需要单独图形能力与取证。
- UI：先窗口与控件语义，再进程内事件与命中，再必要的截图。固定语言 / 分辨率 / UI 缩放；不使用真实系统鼠标。自绘 UI 无法观测或事件无法安全隔离时明确 unsupported。
- 对自定义玩法提供版本化声明式测试契约 / 配方接口，不开放 MCP 任意执行 C# / 脚本 / 反射调用。

## 9. 分阶段执行与完成门槛

| 阶段 | 交付物 | 必须通过的验收 |
|---|---|---|
| P0 已有基础复核 | 当前原型、双版本构建和离线测试基线 | 对照真实代码区分已有能力、计划能力和未验证项 |
| P1 后台可行性门禁 | 双版本引擎适配研究、后台启动实验、焦点 / Tick / 资源观测 | 整个生命周期不抢用户输入；验证可渲染与无头能力，不用最小化冒充保证 |
| P2 隔离与低侵入基线 | 独立 profile、资源策略、Agent 观测审计、对照测试 | 不写正常存档 / Mod 配置，空闲开销有实测，异常不被吞掉或自动修好 |
| P3 确定性执行器与 MCP | 任务状态机、幂等、取消、超时、证据、紧凑高层工具 | 无模型也可跑配方；重复请求不重复启动；客户端断开 / 崩溃有清晰恢复规则 |
| P4 建筑通用回归 | 放置、供材、施工、完工、拒绝与恢复配方 | 真实工作链完成；故意缺料 / 不可达等反例被正确识别；不走开发者强制完工 |
| P5 功能与生命周期 | 已支持类别的功能适配器、存读档、重复运行、Mod 组合 | 至少对代表性建筑覆盖完整链；未覆盖的自定义功能明确标记，双版本分别验证 |
| P6 物品 / 效果 / 后台 UI | 各类别配方与能力矩阵 | 不用直接状态写入冒充触发；UI 不注入桌面输入，视觉与逻辑结论分开 |
| P7 跨客户端与交付 | MCP 配置示例、错误恢复示例、报告格式、完整 README、复现脚本 | 标准客户端互操作；条件允许时轻量模型端到端验证；两版真机证据齐全 |
